# Вместе

## Основной сайт на Netlify: короткие ссылки

На https://stately-bonbon-c5b413.netlify.app/ нажмите «Создать комнату», затем «Скопировать приглашение». Все друзья открывают одну ссылку вида `/#r=16-символов` и подключаются автоматически. Ответные коды не нужны. Ведущий держит вкладку открытой. Комната действует до 6 часов; после обновления страницы ведущего нужно создать новую комнату.

Netlify Functions и @netlify/blobs хранят временные описания соединений. Описания удаляются после подключения; запись комнаты удаляется почасовой очисткой после истечения срока. Чат и синхронизация передаются через WebRTC. Без TURN некоторые VPN и мобильные сети могут не пропускать прямое соединение.

Netlify должен быть связан с этим GitHub-репозиторием. Настройки из netlify.toml: `npm run build`, публикация `dist`, функции `netlify/functions`, Node 24. Для локальной проверки: `pnpm install --ignore-scripts`, `node --test tests/signaling.test.mjs`, `node scripts/build.mjs`.

GitHub Pages остаётся статической копией: короткие комнаты требуют серверных функций Netlify. Ниже описан прежний режим PeerJS и ручной обмен кодами для старых приглашений.


Небольшой сайт совместного просмотра, подходящий для статического GitHub Pages. HTML/CSS/JavaScript без сборки. PeerJS 1.5.5 и его MIT-лицензия сохранены в репозитории: загрузка страницы не зависит от внешнего CDN. Главная страница не подключается к внешним серверам автоматически. PeerJS Cloud используется после создания обычной комнаты; если подключение не установилось за 8 секунд, ведущему создаётся прямая комната. Для гостей недоступной обычной комнаты потребуется новое прямое приглашение.

## Как смотреть

1. Ведущий открывает сайт и нажимает «Создать комнату».
2. Копирует приглашение и отправляет друзьям. Ссылка содержит секрет доступа; не публикуйте её для посторонних.
3. Выбирает «Тестовое видео», прямую HTTPS-ссылку на MP4 или локальный файл.
4. Участники открывают приглашение. Если выбран файл, каждый открывает одинаковую копию с тем же именем и размером у себя. Файл не передаётся и не загружается на GitHub. Имя и размер не доказывают идентичность содержимого.
5. На телефоне участник нажимает «Включить просмотр и звук». Пуск, пауза, перемотка и скорость задаются ведущим. Коррекция времени проходит каждые две секунды, с оценкой разницы часов по ping/pong.

Комната поддерживает до 8 зрителей. Чат хранится только в памяти открытой страницы (до 100 сообщений). Ведущий должен держать страницу открытой; обновление или закрытие завершает комнату. Верните фокус вкладке после переключения приложений на телефоне.

### Если PeerJS не подключается

При проверке 14 октября 2026 сервер PeerJS Cloud блокировал текущий IP через Cloudflare (HTTP 403). Поэтому предусмотрено прямое WebRTC-соединение без сервера сигнализации:

1. Ведущий нажимает «Создать прямую комнату», затем «Скопировать приглашение».
2. Друг открывает ссылку, копирует появившийся код ответа и отправляет его ведущему.
3. Ведущий вставляет код в «Ответный код от друга» и нажимает «Подключить».
4. Для каждого следующего друга ведущий генерирует отдельное приглашение. Неиспользованные приглашения истекают через 5 минут.

Дальше чат и синхронизация работают по тому же протоколу. Приглашение содержит сетевые параметры WebRTC; передавайте его только участникам. Без TURN прямое соединение может не пройти между отдельными мобильными сетями.

## Видео

«Бесстыжие» подключены через третий встроенный плеер, опубликованный на [shameless-series.ru](https://shameless-series.ru/1-sezon-1-seriya). Видео остаётся у внешнего провайдера Alloha, файлы не копируются на GitHub. В меню сайта доступны 11 сезонов; в девятом — 14 серий, в остальных — 12. Выбор сезона и серии передаётся участникам. В плеере при проверке была доступна русская озвучка AlexFilm.

Каждый участник сначала нажимает Play внутри внешнего плеера, разрешает звук и проходит его рекламу. Все выбирают одинаковую озвучку вручную. Общий запуск, пауза и переход к секунде доступны ведущему. Внешний плеер передаёт события времени; гости получают коррекцию через его postMessage-команды. Кнопка «Подстроить время» повторяет коррекцию. Реклама и буферизация идут независимо: синхронизация во время рекламы не гарантируется, перед началом серии дождитесь готовности всех. Сезон и серию переключайте через меню нашего сайта, встроенные переключатели не передают выбор в комнату. Доступность провайдера и его API может измениться.

Встраивание ограничено конкретным источником. Сообщения принимаются только от окна плеера с ожидаемого origin. Используется обычный сторонний iframe: ограниченный sandbox при проверке мешал инициализации этого провайдера. Рекламные окна и поведение самого плеера остаются под контролем провайдера и браузера. Прямые MP4-ссылки и локальные файлы продолжают работать отдельно.

Тестовый ролик — пятисекундное CC0-видео [MDN](https://interactive-examples.mdn.mozilla.net/media/cc0-videos/flower.mp4). Для совместимости с мобильными браузерами используйте MP4 H.264/AAC. MKV и некоторые кодеки браузер может не воспроизвести. Прямой URL должен быть доступен всем участникам; временные ссылки могут истечь.

## GitHub Pages

Загрузите содержимое этой папки в корень репозитория `SDeeKey/raveCopy`, затем в **Settings → Pages → Deploy from a branch** выберите основную ветку и `/ (root)`. Сборка и npm install не нужны. Ожидаемый адрес после успешного развёртывания: `https://sdeekey.github.io/raveCopy/`.

## Ограничения

Это прототип, не гарантия работы во всех сетях. PeerJS Cloud и видеопровайдер — внешние сервисы. Библиотека PeerJS загружается с того же адреса, что и сайт. Собственного TURN-сервера нет; сложные NAT, корпоративные сети и мобильные операторы могут препятствовать соединению. Для стабильной работы в таких сетях потребуется TURN. Мобильная ОС может приостановить фоновые вкладки. Видео буферизуется отдельно у каждого участника; автопауза всей комнаты при буферизации не реализована. Восстановление после ухода ведущего, голосовая связь, хранение видео и интеграция DRM-кинотеатров не реализованы.
